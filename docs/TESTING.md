# Testing

## Automated

| What | Command |
|---|---|
| Go unit tests | `go test ./...` |
| Frontend unit tests (Vitest) | `cd frontend && npm test` |
| Type check | `cd frontend && npm run check` |
| In-app self tests (Linux) | `scripts/build.sh && scripts/selftest.sh <scenario> <arg> [settings.json]` |

`scripts/selftest.sh` runs the real binary (real WebKitGTK webview) with `MF_TEST=<scenario>`; the
frontend loads `src/test/<milestone>.ts`, drives the app through the same APIs and shortcuts a user
would, and exits 0 on pass. Without a display it starts `Xvfb :99` and `openbox` (keyboard focus
needs a window manager). A self-test is always a process of its own: with `MF_TEST` set the single-instance
hand-off is off, so a copy of Monoform that is already open doesn't take the run (and exit with success).

`scripts/readme-media.sh` records the README's clips and gallery from the `demo` scenario (`frontend/src/test/demo.ts`): scripted tours of a generated demo folder with a drawn pointer, on their own 1280×800 X display. It isn't a test (nothing is asserted), but a scene that can't find what it clicks fails, so it also notices broken flows.
